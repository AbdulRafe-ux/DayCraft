## 3. Abstract

DayCraft is a full-stack web application that helps users organise their daily responsibilities. It is built with the MERN stack: MongoDB for storage, Express.js and Node.js for the server, and React.js for the user interface. Users create an account, log in securely, and manage personal tasks with a title, description, category, priority, due date and status. The dashboard summarises progress using figures calculated from the stored data, and lets users search, filter and sort their tasks. Passwords are stored as bcrypt hashes, sessions use JSON Web Tokens in HttpOnly cookies, and every task is linked to its owner so that users can only access their own data. ## 8. Database design and collections

**Collection: `users`**

| Field | Type | Notes |
|---|---|---|
| _id | ObjectId | Generated by MongoDB |
| name | String | Required, up to 80 characters |
| email | String | Required, unique, lowercase |
| passwordHash | String | bcrypt hash, never the real password |
| createdAt, updatedAt | Date | Added by Mongoose timestamps |

**Collection: `tasks`**

| Field | Type | Notes |
|---|---|---|
| _id | ObjectId | Generated by MongoDB |
| title | String | Required, up to 120 characters |
| description | String | Optional, up to 1000 characters |
| category | String | General, Work, Study, Personal, Health, Finance |
| priority | String | Low, Medium, High |
| status | String | Pending, In Progress, Completed |
| dueDate | Date | Optional |
| userId | ObjectId (ref users) | Owner of the task; indexed |
| createdAt, updatedAt | Date | Added by Mongoose timestamps |

**Relationship:** one user has many tasks (`tasks.userId` → `users._id`).

## 9. Main features and CRUD operations

| Feature | How it works | API endpoint |
|---|---|---|
| Register | Validates input, hashes the password, creates a user, starts a session | `POST /api/auth/register` |
| Login / Logout | Checks credentials, sets or clears the session cookie | `POST /api/auth/login`, `POST /api/auth/logout` |
| Restore session | Checks the cookie when the page loads | `GET /api/auth/me` |
| **Create** task | Saves a new task linked to the logged-in user | `POST /api/tasks` |
| **Read** tasks | Returns only the user's tasks, with search, filters, sorting and statistics | `GET /api/tasks` |
| **Update** task | Edits a task, or marks it completed | `PUT /api/tasks/:id` |
| **Delete** task | Removes a task after a confirmation dialog | `DELETE /api/tasks/:id` |

Other features: protected routes, summary cards, progress bar, overdue flag, responsive layout, accessible forms and dialogs.
